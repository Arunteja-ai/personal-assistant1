Authentication and Security Documentation

This guide explains the identity flow used by the AI Personal Assistant Dashboard. The goal is to support a modern SPA frontend while keeping session control, admin security monitoring, and token revocation strong enough for real SaaS behavior.

Security Summary

  • Passwords hashed with bcrypt before storage
  • Short-lived JWT access tokens for API authorization
  • Refresh-token rotation backed by a server-side token store
  • Role-based access control for user and admin paths
  • Login telemetry, anomaly signals, session revocation, and audit logs

JWT Flow Diagram

User submits credentials -> API validates email + password -> Password compared against bcrypt hash -> Access token (JWT) generated -> Refresh token generated and hashed in DB -> Refresh token set as HTTP-only cookie -> Frontend stores access token locally Frontend makes authenticated request -> Axios adds Bearer access token -> API validates token and loads user -> Role and status are enforced If access token expires -> API responds 401 -> Frontend sends /auth/refresh using cookie -> API validates stored refresh-token hash -> Old refresh token revoked -> New refresh token issued -> New access token returned Logout or admin block -> Stored refresh tokens revoked -> New API access denied

Authentication Endpoints

Endpoint Purpose Security Notes
`POST /api/auth/register` Create account, auto-bootstrap first admin or env-defined admin email Triggers secure password hashing and initial token issue
`POST /api/auth/login` Authenticate credentials and create a session Writes LoginHistory with anomaly signals
`POST /api/auth/refresh` Rotate refresh token and mint a fresh access token Uses hashed server-side refresh-token records
`POST /api/auth/logout` Revoke current refresh token and clear cookie Works even if the user is ending a stale session
`POST /api/auth/logout-all` Revoke all active sessions for the logged-in user Useful after password changes or suspected device loss

Role-Based Access Control

Role Capabilities
User Access personal dashboard, goals, todos, habits, notes, transactions, daily logs, profile
Admin All user capabilities plus admin dashboard, user moderation, data control, security panel, audit logs

Suspicious Login Detection

The backend writes a LoginHistory document for every important auth event. It flags signals such as:

  • Repeated failed attempts from the same IP in a short period
  • Repeated failures against the same email address
  • Multi-IP rotation for the same user across a limited time window
  • Blocked-account access attempts
These signals are intentionally simple and explainable. They are suitable for a student SaaS project while still demonstrating how a real admin security panel can surface risk.

Session Management

Every refresh token is stored with user ID, IP address, user agent, creation time, expiry, and revocation status. This enables:

  • User-visible session inspection inside the profile page
  • Admin-visible system-wide session monitoring
  • Per-session revocation for incident response
  • Global revocation when a user is blocked by an administrator
