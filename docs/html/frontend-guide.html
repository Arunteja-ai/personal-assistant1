Frontend Documentation

This document explains the React + Vite frontend for the AI Personal Assistant Dashboard. The user-facing experience is intentionally split into two modes: a calm personal workspace for daily productivity, and a control-plane style admin console for SaaS-grade system operations.

UI Design Summary

  • Stack: React, Vite, React Router, Axios, Tailwind CSS, Recharts
  • Visual direction: warm editorial login surfaces + restrained operational dashboards
  • Interaction model: protected routes, role-aware shells, modal forms, reusable data tables
  • Two dedicated navigation systems: user workspace and admin control plane

UI Structure

Layer Purpose Main Files
Auth Entry Login and registration with guarded redirects into the correct experience. `pages/auth/LoginPage.jsx`, `pages/auth/RegisterPage.jsx`
App Shell Shared sidebar + header layout used by both user and admin spaces. `components/layout/AppShell.jsx`, `components/layout/Sidebar.jsx`
User Workspace Dashboard, goals, todos, finance, notes, habits, daily logs, profile. `pages/user/*`, `utils/resourceConfigs.jsx`

Data Layer JWT-aware Axios client with automatic refresh-token rotation and logout recovery. `api/client.js`, `context/AuthContext.jsx`

Form Validation Strategy

All create/edit modals use a reusable field renderer and validation pass. Required inputs, minimum numeric values, select options, checkbox states, and textarea content are normalized before sending data to the API. Tags are converted from comma-separated input into arrays.

The frontend is built to feel like a real admin product, not a card-based student dashboard. User views stay focused and calm, while admin views prioritize dense signal and direct action.

State Management and Security

Concern Frontend Handling
Access Token Stored locally and attached to outgoing API requests through an Axios interceptor.
Refresh Token Expected as an HTTP-only cookie; automatically rotated when the API returns 401.
Protected Routes Route wrapper blocks anonymous users and restricts admin-only screens.
Role Awareness Post-login redirects send normal users to `/app` and admins to `/admin`.

Responsive Behavior

The layout uses grid-based shells, wraps controls for smaller widths, and keeps tables inside horizontal scroll containers. This allows the product to remain usable on laptop screens, tablets, and mobile devices without breaking core flows.
